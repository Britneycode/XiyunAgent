# XiyunAgent 前端 UI 设计方案

## 设计目标

XiyunAgent 的界面要像一个长期使用的工作台：安静、清晰、可恢复，不使用营销式首页或装饰性卡片堆叠。主界面优先服务于连续对话、任务推进和结果检查；复杂操作放入侧栏、抽屉或设置页。

视觉体验借鉴 OpenHanako 的设置分区、主题和字体自定义能力，但组件和交互保持 XiyunAgent 自己的模式、权限和任务边界。

## 应用外壳

桌面和 Web 使用同一套 React 页面。Electron 只提供窗口和本地 Server 生命周期，不在 renderer 中直接访问文件系统或数据库。

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：工作区 / 当前模式 / 当前模型 / 运行状态 / 设置          │
├──────────────┬───────────────────────────────┬───────────────┤
│ 会话与项目栏  │ 主工作区                       │ 任务/上下文栏  │
│              │ Chat / Work / Code            │ 可收起         │
└──────────────┴───────────────────────────────┴───────────────┘
```

桌面宽屏默认三栏；窄窗口折叠右侧栏，移动浏览器使用单栏并通过抽屉打开会话、任务和设置。布局不依赖固定屏幕尺寸，工作区和代码面板使用稳定的最小宽度与可滚动区域。

## 模式切换

顶栏提供 `Chat`、`Work`、`Code` 分段控件。切换前显示当前会话和工作区，模式切换不会把全部聊天记录复制到新会话，而是创建任务交接摘要。用户手动切换为主，Agent 只能建议切换。

模式视觉只使用轻量状态标识，不用整页换色：

- `Chat`：对话、资料、复习进度。
- `Work`：文件、网页、文档、任务。
- `Code`：项目、终端、Git、测试。

## Chat 页面

### 结构

- 左栏：会话搜索、新建会话、按模式筛选和归档。
- 中间：消息流、引用资料、工具状态、子任务结果和输入框。
- 右栏：当前记忆摘要、资料来源、复习进度或可恢复任务。

输入框支持附件、工作区选择、模型角色选择和停止生成。发送按钮、停止按钮、复制、重试、引用和删除使用图标按钮并提供 tooltip；不要把图标能表达的操作做成大段文字按钮。

### 消息状态

区分用户消息、主 Agent 回复、工具调用、子智能体结果和等待确认。工具调用默认折叠，只显示动作、目标和结果状态；用户可以展开查看命令、文件和审计摘要。

### 备考体验

资料导入后显示来源和页码。总结、讲解、题目、答案和错题使用可折叠的结果块；错题可以直接标记掌握、再次练习或写入学习记忆。

## Work 页面

Work 使用任务工作台布局：左侧文件和资料树，中间文档/网页内容，右侧任务清单和来源引用。每个结论应能回链到原文或文件位置。外部发送、修改原文件和批量操作使用确认条，不用不可逆的自动动作。

## Code 页面

Code 使用项目工作台布局：

```text
项目树 | 对话与任务 | Diff / 测试 / 终端抽屉
```

代码文件使用等宽字体和语法高亮；Diff 面板显示文件、行号、修改块和审查状态。终端面板显示 shell、工作目录、实际命令、退出码和取消按钮。提交、推送、部署和危险命令必须在结果面板提供明确确认。

右侧任务栏显示 coder、reviewer、tester 的模型、状态、进度和结果摘要。并行只读任务可以折叠；修改任务按顺序显示，避免用户误以为多个 Agent 同时写同一文件。

## 设置页

设置采用左侧分类导航和右侧表单内容，分类固定为：

```text
通用
外观
模型
子智能体
记忆
工作区
权限与安全
Skill
插件
关于
```

### 通用

语言、启动行为、默认模式、默认工作区、通知、快捷键和界面密度。

### 外观

浅色、深色、跟随系统、主题色、普通字体、代码字体、字号、行距、圆角和消息紧凑度。所有修改即时预览，并提供恢复默认值。

### 模型与子智能体

Provider、API 地址、模型名称、能力标签和角色允许范围。子智能体页按 `coder`、`reviewer`、`tester`、`researcher`、`tutor`、`memory` 展示默认模型、备用模型和临时覆盖。

### 记忆、权限与插件

记忆页提供范围、类型、置信度、来源和时间筛选；权限页展示当前模式和工作区的实际授权；插件页区分已安装和已启用，并在启用前展示文件、网络、Shell、后台任务和记忆范围。

## 主题系统

主题不是只有一个 accent 颜色，而是由“主题预设 + 表面覆盖 + 用户微调”组成。预设可以一次切换整套应用外观，用户仍可以单独调整字体、字号、密度和圆角。主题由设计令牌驱动，不在组件中硬编码颜色：

```ts
type ThemeSettings = {
  appearance: "light" | "dark" | "system";
  accentColor: string;
  fontFamily: string;
  codeFontFamily: string;
  fontSize: "small" | "medium" | "large";
  density: "compact" | "comfortable";
};
```

### 预设主题

第一版内置一组可直接选择的预设，名称和色彩方向可以继续调整：

```text
System          跟随 Windows 系统明暗和强调色
Graphite        中性灰黑，适合 Code 和长时间工作
Paper           明亮纸张，适合 Chat 和文档阅读
Solarized Light 低对比暖色浅色主题
Solarized Dark  低对比深色主题
Sakura          粉白、柔和的阅读主题
Midnight       深色高对比开发主题
```

每个预设同时定义应用 UI、Markdown 阅读区和代码区三套 token，避免聊天界面好看但代码和文档区域对比度不足。Solarized 和 Sakura 的设计方向参考 HanaAgent 已安装资源中的主题预设，但不直接复制其 CSS 或资源文件。

设置页使用主题网格，每个主题显示名称、明暗标签、三到五个色块和小型 Chat/Code 预览。点击主题立即应用；“应用”按钮不是必需的，提供撤销和恢复默认即可。当前主题在卡片上显示选中状态，键盘可操作。

### 主题包格式

主题包支持 `theme.json`、可选预览图和版本字段：

```json
{
  "id": "sakura",
  "name": "Sakura",
  "version": 1,
  "appearance": "light",
  "tokens": {
    "bg": "#fffafc",
    "surface": "#ffffff",
    "text": "#352b32",
    "muted": "#82727b",
    "border": "#eadde3",
    "accent": "#c85b83",
    "codeBg": "#2f2730"
  },
  "fonts": {
    "ui": "system-ui",
    "reading": "serif",
    "code": "Consolas"
  }
}
```

导入主题时先校验 ID、版本、颜色格式、对比度和 CSS 属性白名单；主题只能写入自己的 token，不能注入任意 CSS、脚本、网络请求或插件权限。主题导入与插件导入分开，主题包不具备执行能力。

字体只使用系统已安装字体，缺失时回退到系统字体，不自动下载外部字体。普通界面字体、阅读字体和代码字体可以分别选择；主题预设提供默认字体，但用户选择优先级更高。

## 状态和错误

所有页面必须设计加载、空状态、错误、离线、等待确认和权限拒绝状态。错误信息说明发生了什么、是否已修改文件或数据、下一步能做什么；不要只显示“请求失败”。

本地 Server 未启动时，桌面端显示连接状态和重启入口。模型不可用时显示 Provider、角色和可用回退，不静默切换到未授权模型。

## 前端实施顺序

1. 抽取现有 `apps/web/src` 的主题 token、设置和 Chat 页面为共享 UI 基础。
2. 统一 App Shell、模式分段控件、会话栏、任务栏和确认条。
3. 阶段 2 增加记忆管理页和候选确认抽屉。
4. 阶段 3 增加子智能体任务面板和模型选择器。
5. 阶段 4 增加 Code 项目树、Diff、终端和审批面板。
6. 阶段 5 增加 Work 文档、网页来源和任务工作台。
7. 阶段 6 增加 Skill/插件管理和权限详情页。

## UI 验收

- 桌面宽屏、窄窗口和手机浏览器不发生文本、按钮或面板重叠。
- Chat、Work、Code 的模式和工作区始终可见。
- 所有高风险操作都能看到目标、影响范围和确认入口。
- 子智能体的模型、状态和结果可追踪。
- 主题、字体、字号和密度修改即时生效并可恢复默认。
- 错误、空状态、加载和权限拒绝均有可执行的下一步。
